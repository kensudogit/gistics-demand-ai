# 需要予測と配送最適化

## 需要予測
1. ベースライン: 季節ナイーブ、移動平均、曜日別中央値。
2. 特徴量: 過去の売上ラグ、曜日/祝日、在庫/欠品、販促、予測発行時点で利用可能な気象予報。
3. 時系列のrolling-origin backtest。SKU/拠点/期間でWAPE、MAE、Biasを評価。
4. 必要に応じLightGBM/XGBoost、階層整合、確率予測を検討。
5. モデル・特徴量・データ期間・ハイパーパラメータ・メトリクスをバージョン管理。
6. データドリフト、欠品バイアス、推論欠損、再学習条件を監視。

## 配送ルート
- TSP（1車両）とVRP（複数車両）を区別。容量・時間窓・勤務時間を制約化。
- OR-Tools Routing Solverを第一候補。交通行列は外部経路サービス等から取得。
- 目的: 総移動時間、遅延、車両数、コストの加重最小化。重みの業務合意を取る。
- 実行可能解がない場合は制約違反理由と未割当配送先を返す。架空の最適解を返さない。
- デモの全探索TSPは小規模・制約なし・距離行列入力のみ。生産用途では使用しない。
